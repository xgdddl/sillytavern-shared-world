# 连接与游玩

## 安装和更新

在酒馆「安装扩展」填写 https://github.com/xgdddl/sillytavern-shared-world ，选择仅为自己安装。已有用户在「管理扩展」中更新。刷新后在左下角魔法棒打开「共叙 · 联机世界书」。无需另开酒馆实例或运行本项目的开发服务器。

## 一次配置共同记录

1. 选择一个与插件代码分开的 GitHub 数据仓库。故事不希望公开时使用私有仓库。
2. 仓库资源管理员为参与者授予协作者写权限；参与者自行接受邀请。这个权限用于存储，没有插件内的房主或剧情裁定权。
3. 每位玩家使用自己的账号凭据。令牌只能使用本人已有的权限，不会因为填写令牌自动获得别人的仓库访问权。
4. 在共叙「设置」选择 GitHub，填写 owner、repo、branch、数据目录。不要将个人管理密钥发给朋友。
5. 保存设置，再点「检查读写连接」。成功后显示本人账号，验证一次隔离的连接检查写入和读回。写入只涉及 `_checks/`，不发送聊天正文。
6. 凭据默认只留在当前会话。需要跨刷新保留时，可自行设置本机解锁口令并加密保存；换设备需要重新授权或填写本人凭据。

GitHub 的 Fine-grained PAT 支持资源拥有者或组织成员的部分场景，但目前不支持部分外部/仓库协作者写入场景；不能一概要求所有人都用 Fine-grained PAT。Classic PAT 的权限范围更广，不愿使用时可选择你们自己的组织成员与仓库权限方案。详情以 [GitHub 令牌限制](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#fine-grained-personal-access-tokens-limitations) 为准。文件接口需要相应 Contents 读写权限，参阅 [GitHub Contents API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)。不自动申请或扩大你的权限。

本版支持直接填写已有令牌，没有内置免账号匿名写入或 OAuth 一键授权服务。无需部署本项目的公共服务器；GitHub 是共同记录服务。它有配额和限流，不能保证高频十人场景的即时性。

## 开始共同故事

1. 每人打开同一版本角色卡的角色聊天。卡内设定和绑定的外置世界书会参与版本识别；不相同会提示，不混合存档。
2. 任意玩家建立世界，填写共同开场与时间起点。他不会获得额外游戏权限。
3. 复制 `sw1:` 开头的邀请。其他人在自己的酒馆粘贴邀请；邀请包含存储地址和世界编号，不包含密钥，也不依赖创建者的 localhost 地址。
4. 选择已有的本人人物、创建人物或接手未归属 NPC。每人在同一世界最多拥有三个人物；已经归属他人的人物不能抢占。
5. 设置托管范围，然后在所选聊天开启联机。一次控制一个人物；换设备时可主动转移控制，旧页面不能继续续租。
6. 正文仍由本人的酒馆生成。扩展读取共同事实、生成上下文，正文结束后额外提取变化，核验记录结构、原文证据和明确冲突，再上传并读回。

## 同场景、离线和冲突

已经有见面经历且同地点的人物可自动进入现场等待，也可以在年表里选择互动对象。相互行动允许小幅故事时间偏差，不强制将不同日期玩家拉到一起。

现场真人都有输入时，各自生成正文。两份结果先作为候选；对同一现场人物的身份、地点、状态一致，才把两段经历一起确认。明确不一致时保留草稿，不额外调用 AI 判胜负，也不按上传先后裁定。

对方未提交现场结果并超过一分钟时，仅在其授权范围内继续；对方已经提交矛盾结果时不能用超时覆盖。输入等待、结果等待和模型处理是不同阶段，整轮总耗时不承诺一分钟内。

退出并托管允许其他正文按约定承接；退出留作背景人物则不替其安排新的行动。全员离线时不主动生成剧情；已有历史仍存放在数据服务，有权限的人可读取。

提取失败、网络失败、时间不明确或共同事实冲突时，到「年表」查看原文、修改草稿后重新提取，或保留个人草稿。它不会替你改写聊天或默默回滚正式事实。

## 模型和费用

不填额外接口就复用当前酒馆模型，但正常一轮正文之后仍会多一次资料提取。长期摘要可手动执行，默认每增加约二十段记录尝试整理，会增加用量。额外接口目前使用 OpenAI 兼容 Chat Completions 格式，原生其他格式请通过酒馆现有接口或兼容网关。

合理性接口为预留配置，不自动运行。叙事中隐含的矛盾仍可能被模型漏识别，结构校验不能代替语言理解。遇到提取失败可保留正文，换可用模型后直接重试，不需要丢掉原文。

自定义酒馆接口开启流式时，提取和摘要沿用本地酒馆后端的流式请求，避免后台 `generateRaw` 强制非流式导致中转不兼容。额外接口可单独勾选流式；支持 SSE 和普通 JSON 返回。若中转明确返回 `PROXY_GENERATION_DISABLED`，需要先启用该服务的生成能力或选择一个可用接口，插件不能绕过服务的禁用设置。

## 备份与恢复

导出世界包含完整人物、物品和历史，不含 API Key。导入会恢复为独立副本，保留原世界。GitHub 身份随本人账号恢复；本机身份可以单独导出编号文件，适用于受信任协作，不作为网络认证凭据。

大存档会自动分片并校验；分片齐全后才更新索引。旧分片仍留在数据仓库供恢复，不自动永久清理。仓库历史也会保留文件版本。
