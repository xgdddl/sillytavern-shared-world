# 共叙 · 联机世界书

SillyTavern 共享故事扩展，当前版本 **1.0.0-rc.3（功能候选版）**。提供共同记录、正文提取、现场结果确认、托管、人物物品发现、身份恢复与存档恢复。仍需要真实玩家持续游玩验收，不承诺模型能识别一切隐含矛盾。

各自在自己的酒馆里扮演人物，正文沿用自己的模型，通过共同的世界记录承接彼此的经历。没有游戏房主，不启动额外的酒馆实例，也不要求部署本项目的公共服务器。

## 用 Git URL 安装

1. 打开酒馆顶部的「扩展」，点击「安装扩展」。
2. 填写仓库地址：

       https://github.com/xgdddl/sillytavern-shared-world

3. 点击「Install just for me / 仅为我安装」，按提示重新加载页面。
4. 在左下角魔法棒菜单中点击「共叙 · 联机世界书」。

扩展设置里也保留「共叙」按钮。安装之后默认不启用联机，不改动现有聊天、角色卡、核心世界书或预设。打开角色聊天、选择世界与人物后，才可开启该聊天的联机。已安装旧版的用户在管理扩展中更新，然后刷新页面；同一世界的所有玩家都须更新。新版本读取旧记录，写入时升级为 shared-world/3；旧插件不能读取或写入升级后的世界。

初次联机请按 [连接与游玩说明](docs/SETUP.md) 完成一次数据仓库授权。安装扩展和连接共同存档是两个步骤。

## 当前功能

- 标准扩展安装、左下角魔法棒入口、适配手机和电脑宽度的面板。
- 同卡多世界、当前数据来源的世界列表、编号/邀请与世界导出。
- 固定文字人物模板；每人最多拥有 3 个人物，当前聊天一次选择 1 个；已归属人物不能被他人接手。
- 未归属 NPC 接手、开局物品登记、人物与物品归属记录。
- 具体到「第 N 天 HH:mm」的故事时间，以及按时间读取历史状态。
- 正文生成前注入共同事实，结束后提取变化；正文由各自模型决定，不增加双方 AI 复核。
- 角色托管范围、退出方式、最多一分钟的现场行动等待。
- 冲突提示、重试与个人草稿保留；不静默改写原正文。
- 本机演示存储与 GitHub 实验存储适配，版本检查、重试和写入读回。
- 变化提取、摘要等用途可分别配置兼容接口，未配置时复用当前酒馆接口。
- 正文中新人物、新物品自动登记，逐字原文证据校验；别名引用、物品消耗、数量及损坏记录。
- 共同开场、独占世界事实与全局未来节点接入正文；已有事实的交接必须承接原值。
- 真人现场结果先保存为候选；双方人物状态一致才一起确认，冲突不会按上传速度判胜负。
- 对方未提交结果且等待到期时，仅在其授权托管范围内继续；已有双方冲突不能通过超时覆盖。
- 本机身份备份；GitHub 使用已验证的本人账号，换设备可恢复同一归属。
- 同一玩家的设备控制租约、主动转移控制、真正区分托管和只保留背景。
- 自带数据来源的跨设备邀请、失败正文修改和重新提取、独立副本恢复。
- 本机 AES-GCM 加密保存和口令解锁凭据；持久长期摘要与自动整理。
- 大世界分片和完整性校验，读缓存和条件请求，长年表分页。

## 世界数据与模型接口

插件安装仓库用于分发代码，和世界数据来源是两回事。

模型接口负责生成或提取文字；存储接口负责上传和读取共同记录。默认「本机演示」只保存于当前浏览器，不会同步到朋友的设备。

GitHub 模式需要可读写的数据仓库和每位玩家本人的凭据。每个世界使用带版本保护的记录，避免盲目覆盖其他玩家的更新。超过 600 KB 自动分片，分片齐全后才更新共同索引，读取时校验摘要；单世界上限 30 MB，最多 100,000 条历史、2,000 个人物、10,000 件物品。达到边界明确报错，不截断历史。目录达到服务列表上限时使用邀请或编号直接加入。

API 密钥默认只留在当前页面会话，不进入共同世界、导出文件或邀请。可自选本机口令加密保存；口令不上传。不要把个人管理密钥分发给朋友。GitHub 协作者令牌存在服务自身的适用限制，见连接说明。

## 原型边界

本版是完整功能链路的发布候选，不等于已完成所有卡、手机真机和长期故事验收。

- 角色设定、托管和剧情合理性最终仍受模型理解能力影响；没有独立 AI 重新裁定正文。
- 目前是受信任玩家协作，仓库管理者或写权限持有者能绕过插件直接改文件，不提供竞技防作弊保证。
- GitHub 采用轮询和版本保护，不是即时推送；频繁提交可能触发服务限流。资料模型处理、现场输入等待、现场结果等待各自有期限，整轮总耗时不保证一分钟内。
- 自动相遇以已记录的见面经历为依据；遇到地点别称、复杂同名实体或不确定时间会要求确认，不擅自猜测。
- 外置世界书会参与版本识别；不同预设仍可能导致模型行为不同。活动角色聊天支持优先，群聊和所有第三方生成扩展的组合不做无条件兼容承诺。
- 已确认的历史不通过删楼或重生成回滚。草稿可改，世界可恢复为副本；正式因果变化须由新正文承接。
- 全员离线时不主动调用模型推进；有存储权限的新玩家仍可从服务读取历史。

后续工作见 [开发路线](docs/ROADMAP.md)。

## 开发与演示

Node.js 20+，无第三方运行依赖：

    npm run check
    npm test
    npm run dev

开发服务器仅监听本机。终端显示演示页地址，默认端口 8787。演示页使用明确标注的虚构人物和事件，数据只留在当前浏览器；它不是实际远程联机证明。

运行时文件为 manifest.json、index.js、style.css 和 src/。不需要启动开发服务器才能在酒馆里使用扩展。

## 代码分工

| 模块 | 职责 |
|---|---|
| index.js / src/menu.js | 加载、设置入口与魔法棒菜单 |
| src/domain.js | 固定模板、归属、事件检查与历史投影 |
| src/storage.js / src/service.js | 存储适配、版本保护与场景等待 |
| src/controller.js | 聊天绑定、人物、正文提取与草稿 |
| src/prompts.js / src/ai.js | 动态上下文、变化提取与摘要接口 |
| src/tavern.js | 酒馆生成事件、临时注入与聊天切换保护 |
| src/panel.js / style.css | 面板与响应布局 |
| demo/ / tests/ | 本机演示与本地检查 |
